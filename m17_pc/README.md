# m17_pc：ソフトウェアだけの M17 局

無線機を使わずに、PC だけで **M17 リフレクター**（mrefd、UDP 17000）に接続して、
**音声の受信と送信**をするアプリです。声の圧縮には、公開されている **Codec 2**（LGPL-2.1）を使います。
特許のある方式や、他社の部品は使っていません。

```
 マイク → Codec 2 3200 で符号化 ─→ 40 ms ごとに 1 パケット（54 バイト） ─┐
                                                                       ├ UDP 17000 ⇄ M17 リフレクター
 スピーカー ← 適応再生 ← Codec 2 3200 / 1600 で復号 ←──────────────────────┘
```

| ファイル | 中身 |
|---|---|
| `build_m17_pc\m17_pc.exe` | 画面付きのアプリ |
| `build_m17_pc\m17_cli.exe` | 画面なし（試験・スクリプト用）。`--tx-wav` で WAV を「マイクの代わり」に送れる |
| `build_m17_pc\m17_test.exe` | M17 のパケットと符号の検査（全部通れば終了コード 0） |
| `m17.c` | M17 のパケット：コールサインの base-40 符号、CRC-16（多項式 0x5935）、CONN・PONG・DISC、54 バイトのストリームパケット |
| `m17_engine.c` | 局の中心：接続（CONN → ACKN、PING に PONG で答える）、受信の復号と再生、PTT 中の送信 |
| `m17_gui.c` | 画面 |
| `license_check.c` | 免許の照合：総務省 電波利用ポータルの「無線局等情報検索」（アマチュア局、呼出符号）の検索結果のアドレスを作る |
| `audio_win.c`・`mic_win.c`・`wav.c` | スピーカー（揺らぎを吸収する適応再生）、マイク、WAV の保存 |
| `m17_parrot.c` | アプリに内蔵の試験用リフレクター（127.0.0.1 だけ。自分の送信を 1 秒後に送り返す。同じモジュールの他の局へは中継） |
| `icon.html`・`make_icon.ps1`・`m17_pc.ico` | アイコン（独自の図柄：濃紺の地に緑の波形と「M17」） |
| `hosts\M17Hosts.txt` | リフレクターの一覧（1 行に「名前 ホスト ポート  # 説明」、UTF-8）。M17 リフレクター 46 件と内蔵パロット。ビルドで `build_m17_pc\hosts\` に写る（**ビルドのたびに上書きされる**ので、自分で足した行は元の `m17_pc\hosts\` にも入れる） |

## M17 のパケット（インターネット側）
* 接続：`CONN` ＋ 自局コールサイン（6 バイト）＋ モジュール（1 文字）＝ 11 バイト。答えは `ACKN`（受け入れ）か `NACK`（拒否）。
* 生存確認：リフレクターが `PING` ＋ リフレクター名を送ってくるので、`PONG` ＋ 自局コールサインで答える。
* 切断：`DISC` ＋ 自局コールサイン。
* 音声：`M17 ` ＋ ストリーム番号（2）＋ 宛先（6）＋ 送信元（6）＋ 種類（2）＋ META（14）＋ フレーム番号（2）＋ 音声（16）＋ CRC（2）＝ 54 バイト。
  音声 16 バイトは Codec 2 3200 の 20 ms 分（8 バイト）が 2 つ。最後のパケットはフレーム番号の最上位ビットが 1。
* コールサインは base-40 で 6 バイトに詰める（最大 9 文字、使える文字は A〜Z・0〜9・`-`・`/`・`.`・空白）。宛先 `@ALL` は全員宛て。

## ビルド
まず Codec 2 をビルドしておく（1 回だけ）。`%USERPROFILE%\tools\codec2` に v1.2.0 のソースを置き、w64devkit で：
```
cmake -S %USERPROFILE%\tools\codec2 -B %USERPROFILE%\tools\codec2\build_w64 -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release -DUNITTEST=OFF -DBUILD_SHARED_LIBS=OFF
cmake --build %USERPROFILE%\tools\codec2\build_w64
```
そのあと：
```
m17_pc\build.bat
```

## 使い方（m17_pc.exe）
1. 「一覧の絞り込み」に名前・国・説明の一部（例 `M17-M17`、`GB`、`QuadNet`）を入れ、「リフレクター」から選ぶ（ホストとポートが入る）。
   一覧にないものは、ホストとポートを入れて **「追加」**（名前と説明を聞かれ、`hosts\M17Hosts.txt` の最後に 1 行増える）。
   接続中に「追加」を押すと、リフレクターが名乗った名前（例 `M17-M17`）が名前の欄に最初から入る。
   要らないものは一覧で選んで **「削除」**（確認のあと、その行が消える。接続中は押せない）。
2. モジュール（A〜Z）を選ぶ。宛先はふつう `@ALL` のまま。
3. コールサインを入れる（9 文字まで）。
4. 「接続」→「接続中」になったら、交信が来ると鳴り、相手・宛先・方式・欠落率が出る。
5. **送信**：「送信 PTT (F2)」か **F2** で始め、もう一度押すと終わる。180 秒で自動的に止まる。最初の送信の前に確認が出る。
6. **試験**：「パロットで試す」を押すと、アプリの中で試験用リフレクターが動き、ホストが 127.0.0.1、ポートが 17000 になる。
   「接続」して F2 で話すと、止めた 1 秒後に自分の声が返ってくる（ネットには出ない。このときは送信の確認も出ない）。
   もう一度押すと止まる。ポートは `m17_pc.ini` の `parrot_port` で変えられる。
7. 「受信した通話を recordings\ に保存」を入にすると、`recordings\` に通話ごとの WAV ができる（自分の送信のマイク音も `_tx_mic.wav` で残る）。

## 免許の照合
「接続」を押すと、入れたコールサインで、総務省 電波利用ポータルの「無線局等情報検索」（アマチュア局）の検索結果を
**既定のブラウザで開きます**（同じコールサインはアプリを閉じるまで 1 回だけ）。一覧に「（コールサイン）」がない場合、
無線局の免許を受けずに送信すると電波法により罰せられる可能性がある旨を表示します。**照合の結果にかかわらず、アプリはそのまま使えます。**
* 判定するのは自分の目です（アプリ自身は総務省のサイトに何も送りません。総務省の Web-API はアプリからの問い合わせを
  HTTP 403 で断ったため、ブラウザで開く方式にしました）。
* `/P`・`-1` などの付いたコールサインは、元のコールサインで検索します。日本のアマチュア局の形式（JA〜JS、7J〜7N、8J〜8N）でないものは照合しません。
* 開いたページを見ると、コールサインが総務省のサイトに送られます。
* `m17_pc.ini` に `license_check=0` と書くと、照合しません。

設定は `m17_pc.ini`（プログラムの横）に残ります。送受信の音量は `m17_pc.ini` の `tx_gain_db`・`rx_gain_db`（dB、整数）で変えられます。

## 試験（m17_cli.exe）
```
build_m17_pc\m17_cli.exe parrot N0CALL --module C --tx-wav 声.wav --tx-at 1 --wav 保存先 -n --time 24
```
ホストの代わりに `parrot` と書くと、内蔵の試験用リフレクター（127.0.0.1、`--port` の番号、既定 17000）を起動してつなぐ。

## 無線機モード（2026-11-16）
「接続先」を **無線機（サウンドカード）** にすると、リフレクターの代わりに、PC のサウンド入出力につないだ FM 無線機と
M17 で送受信します。4値FSK の変調・復調は PC の中で行います（ESP32-A1S モデムと同じ `m17_modem/core` のコード）。
A1S は要りません。

* つなぎ方：無線機の **9600bps 用 DATA 端子**（6 ピン ミニDIN）の 1 番（DATA IN）← PC の出力、4 番（DATA OUT 9600）→ PC の入力、2 番 GND。
  USB のオーディオインターフェース（Digirig など）を使うと楽です。
* PTT：「無線機の設定…」で、なし（VOX）・RTS・DTR・CI-V（Icom、IC-705 はアドレス A4）から選び、COM ポートを入れる。
* 送信レベル（既定 -10 dBFS）・送信遅延（PTT を入れてから信号を出すまで、既定 150 ms）・変調の反転も同じ画面で。設定は `m17_pc.ini` の `[radio]`。
* 入出力に「内部で折り返す」を選ぶと、音を出さずに PC の中で送信を受信に戻す（試験用）。
* Windows の音声の「拡張機能」や自動音量調整は切ってください（4値FSK の波形がくずれます）。
* **マイク端子・スピーカー端子では通りません。** 300 Hz〜3 kHz の帯域を通すと、雑音がなくても 1 フレームも復調できない
  ことを試験で確認しました（下の表）。IC-705 の USB オーディオも帯域が制限されているとみられ、通る報告は見つかっていません。

```
build_m17_pc\m17_cli.exe radio JA1TEST --loop --tx-wav 声.wav --tx-at 1 -n --time 6           (折り返し)
build_m17_pc\m17_cli.exe radio JA1TEST --rin 2 --rout 3 --ptt COM5:rts                       (実際の無線機)
build_m17_pc\m17_cli.exe radio JA1TEST --rin 1 --rout 1 --ptt COM4:civ --civ-addr A4          (Icom の CI-V で PTT)
```

| 折り返し試験（3 秒の声、76 フレーム） | 受信できたフレーム | EVM（平均） |
|---|---|---|
| 雑音なし | 76（欠落 0） | 0.003 |
| SNR 12 dB | 76（欠落 0） | 0.142 |
| SNR 8 dB | 76（欠落 0） | 0.225 |
| 変調の反転 | 76（欠落 0、「inverted」と表示） | 0.003 |
| 300 Hz〜3 kHz の帯域（マイク・スピーカー経路のまね） | **0** | — |

**まだ確かめていないこと**：実際のサウンドカードと無線機での送受信、PTT（RTS・DTR・CI-V）。電波を出すのは、M17 での送信が免許の範囲に入ってから。

## 中継モード（2026-11-16）
「接続先」を **中継（無線機 ⇔ リフレクター）** にすると、無線機とリフレクターに同時につなぎ、通話を中継します。

* **無線機 → リフレクター**：無線機で受けた M17 の通話を、そのままリフレクターへ送る（いつも入）。送信元は話した局のコールサイン。
  途中から受けた通話は、LICH から送信元がわかってから送る。
* **リフレクター → 無線機**：「無線機の設定」で **「リフレクターの通話を、無線機から送信する」** に印を付けたときだけ。
  リフレクターに誰かが話すたびに、**自動で電波が出ます**（接続のときに確認が出ます）。M17 の送信元は既定で **自局のコールサイン**
  （相手のコールサインのままにする設定もあり）。届く間隔のむらに備えて、送信の頭に 200 ms の余裕（`[radio]` の `relay_cushion_ms`）。
* 同時に中継するのは 1 通話だけ（先に始まった方）。中継にも送信時間の上限（180 秒）がかかる。
* 自分の PTT は、リフレクターと無線機の両方に送る。
* 自局が無線機から送信している間に受けた信号は、中継しない（中継の輪にならない）。

```
build_m17_pc\m17_cli.exe m17.example.net JA1TEST --module A --relay --rin 2 --rout 3 --ptt COM5:rts
build_m17_pc\m17_cli.exe parrot JA1GW --relay --relay-to-radio --loop --test-rf 声.wav:JA1RF:2 -n --time 14   (試験)
```

試験（内部折り返し＋内蔵パロット、3 秒の声）：
* 無線機の試験局 JA1RF の通話 → リフレクターへ 75 パケット → パロットが 1 秒後に返す → 無線機から 75 フレーム送信、
  自局のコールサインで欠けなく復号できる。中継した電波がまた中継されることはない。
* 「リフレクター → 無線機」を切った既定の設定では、返ってきた通話は送信しない。
* 画面版：中継モードで PTT 3.2 秒 → リフレクターと無線機の両方へ 81。パロットの返しを無線機から送信（81 フレーム）。

### 無線機からの操作（宛先コマンド、2026-11-16）
フィールドの無線機から、**宛先（DST）欄**に次を入れて短く送信すると、中継モードの m17_pc がつなぎ先を変えます
（M17Gateway・mspot と同じ約束事）。コマンドの通話はリフレクターへは送りません。

| 無線機の宛先 | 動作 | 返事（無線機の宛先表示＋ビープ） |
|---|---|---|
| `M17-XXX A` | リフレクター M17-XXX のモジュール A につなぐ（9 文字目がモジュール。名前は `hosts\M17Hosts.txt` で探す） | `M17-XXX A`・2 回（つながった）／`LINK FAIL`・3 回（断られた・15 秒応答なし）／`NOT FOUND`・3 回（一覧にない） |
| `UNLINK` か `U` | 切断する | `UNLINKED`・1 回 |
| `INFO` か `I` | 今のつなぎ先を知らせる | `M17-XXX A`・2 回／`UNLINKED`・1 回 |
| `ECHO` か `E` | 話した声（60 秒まで）を 1 秒後に送り返す | 宛先 `ECHO` で自分の声 |
| それ以外（`@ALL` など） | ふつうの通話としてリフレクターへ中継 | — |

* 返事の送信元は自局のコールサイン。結果は宛先欄に入れて送るので、無線機の表示で読めます（音声の案内はありません）。
* 返事は、チャンネルが空いて（受信中・送信中でない）から送ります。続けて操作すると、新しい返事が前の返事に置き換わります。
* 中継モードは、リフレクターを入れずに（未接続で）始めることもできます。無線機から `M17-XXX A` でつなぎます。
* 「無線機の設定」の「無線機からの操作を受け付け、返事を送信する」で切れます（既定は入）。コマンド版は `--no-commands`・`--no-answers`。

```
build_m17_pc\m17_cli.exe - JA1TEST --relay --rin 2 --rout 3 --ptt COM5:rts      (未接続で始め、無線機からつなぐ)
```

試験（内部折り返し＋別プロセスのパロットを `M17-TST` として一覧に入れて）：試験局 JA1RF が無線機から順に
`INFO` → `UNLINKED` の返事／`M17-TST B` → モジュール B につながり（パロット側でも確認）`M17-TST B` の返事／`@ALL` の通話 →
リフレクターへ 75 パケット、返ってきた通話を無線機から 75 フレーム／`INFO` → `M17-TST B`／`ECHO` → 3.0 秒の声を
1 秒後に送り返し（75 フレーム欠けなし）／`UNLINK` → 切断（パロット側でも確認）、`UNLINKED` の返事。
一覧にない `M17-ZZZ A` → `NOT FOUND`。返事はどれも、自局のコールサインで欠けなく復号できた。
**まだ**：本物のリフレクターへのリンク、実際の無線機の表示での確認、途中から受けたコマンド通話（LICH から宛先がわかる場合）。

**注意**：ほかの人の通話を自局の電波で送る（リフレクター → 無線機）のは、免許や運用の条件によっては認められません。
使う前に確かめてください。無人で動かさず、そばで監視してください。

## リフレクター一覧の出どころ（2026-11-14）
* N6JET の M17 リフレクター一覧（M17 の登録簿から英語圏の国を抜き出したもの、2026 年 7〜8 月に確認済み）：https://n6jet.com/m17-reflectors-english.html 。M17-M17 は QuadNet（https://openquad.net）の案内とも一致。
* 2026-11-14 に、各リフレクターのダッシュボード（Web ページ）が応答するかと、ホスト名の DNS を確かめた。応答した 35 件は印なし、ダッシュボードがない・応答しない 11 件は「(未確認)」。ホスト名の向き先が変わりダッシュボードも応答しない 2 件（M17-835、M17-NET）は入れていない。UDP（M17 そのもの）では確かめていない（接続にはコールサインが要るため）。
* dvref.com と RefCheck.Radio の一覧は、ボット確認やコールサインの登録が要るので使っていない。

## 確かめたこと（2026-11-14）
* 一覧の追加・削除：画面で「追加」→ 名前と説明を入れると `hosts\M17Hosts.txt` の最後に 1 行増えて一覧で選ばれ、「削除」→ 確認でその行だけが消える（ほかの行とコメントはそのまま）。
* 免許の照合：作ったアドレスで、公開の局 JA1RL の検索結果（26 件）が表示される。`m17_cli --check JA1RL/P` はアドレスを表示する（`/P` を除いて検索）。
* `m17_test`：CRC が M17 仕様書の検査値（空 = FFFF、"A" = 206E、"123456789" = 772B、00〜FF = 1C31）と一致、
  コールサイン `AB1CD` が仕様書の例 `00 00 00 9F DD 51` と一致、パケットの組み立てと読み取りが往復する。
* パロット経由の往復：9.3 秒の声 → 232 パケット送信 → 232 パケット受信、欠落 0、CRC 誤り 0。
  受信した音は、Codec 2 公式の `c2enc` / `c2dec` で作った音と **全サンプル一致**。
* 画面版：「パロットで試す」→「接続」→ PTT でマイクから 3.2 秒送信し、1 秒後に 79 パケットが戻って受信履歴に出る。
  同じモジュールにつないだ別の局（m17_cli）の送信も中継されて受信できる。
* **本物のリフレクターにはまだつないでいない**（実際の通話の受信、他局との交信）。

## できないこと（今の版）
* 送信は Codec 2 3200 だけ（1600 ＋ データの送信はしない）。受信は 3200 と 1600 を再生する。
* META（位置情報・テキスト）は送らず、受信しても表示しない。
* パケットモード（M17P）、暗号化には対応しない。
* 付属の一覧は英語圏（米・加・英・豪・NZ）のリフレクターだけ。日本のリフレクターは見つからなかった。
* A1S を USB モデムとして使う方式はまだ。中継で、複数の通話を同時に扱うことはしない。
