# m17_modem：ESP32-A1S で作る M17 モデム（Codec 2 ＋ 4 値 FSK）

FM 無線機のデータ端子（9600bps 用）につないで、M17 の音声を送受信するための箱です。
声の圧縮は Codec 2（LGPL-2.1）、電波の形式は M17 仕様の第 1 部（4800 シンボル/秒の 4 値 FSK）。
特許のある方式や、他社の部品は使っていません。

```
 基板のマイク（右 ADC, RIN1）→ 8 kHz → Codec 2 3200 → M17 フレーム → 4FSK 48 kHz → 左 DAC（LOUT1 = PHONE 端子の先端）→ 無線機へ
 無線機から → LINE IN 端子の先端（左 ADC, LIN2）→ M17 復調 → フレーム → Codec 2 → 8 kHz → 右 DAC（PHONE のリング、右スピーカー）
```

送信と受信は同時に動きます。PHONE 端子と LINE IN 端子を 3.5 mm ステレオのオス－オスケーブルでつなぐと、
自分の送信を自分で受信できます（折り返し試験）。無線機とのやり取りは **先端（左）だけ** を使います
（先端は差し込みが浅くても必ず接触する。リングは接触が不安定なことがあった）。

* ESP32（初代）は 16 ビットステレオの I2S で左右の語を入れ替えて送受信する（出力の 1 語目 → 右 DAC、入力の 1 語目 ← 左 ADC）。
  `main.c` の `OUT_MODEM` などは、この実測に合わせてある（起動ごとに変わらないことを 4 回の起動で確認）。
* `diag` コマンドで、声（リング）と変調（先端）に 1 kHz を出し、どの入力に届くかを測れる。

| フォルダ・ファイル | 中身 |
|---|---|
| `core\m17_rf.c` | M17 の電波側：LSF とストリームフレーム（畳み込み符号 K=5、P1/P2 パンクチャ、Golay(24,12) の LICH、QPP インターリーブ、ランダマイザ、同期語）、軟判定ビタビ |
| `core\m17_modem.c` | 変調（RRC α=0.5・81 タップ、48 kHz）と復調（整合フィルタ、同期語の検出、復号して LSF かストリームかと極性を判定、フレーム全体の EVM が最小になる 1/8 サンプル単位のタイミング、利得と直流の推定） |
| `pc\m17_rf_test.c` | PC での検査と往復試験（WAV → Codec 2 → M17 → 4FSK → 雑音・直流・低域カット・極性反転 → 復調 → 照合） |
| `esp32\` | ESP32-A1S（ES8388 版）のファームウェア。`components\codec2`（Codec 2 の必要な部分だけ）、`components\m17core`（`core` と `m17_pc\m17.c`） |

## 確かめたこと（2026-11-14）
* `m17_rf_test`：Golay の検査ビットが仕様書の生成行列 12 行と一致、インターリーブ表が仕様書と一致、同期語の記号が一致。
* PC の往復（9.2 秒の声、231 フレーム）：きれいな通信路、極性反転、直流 4000、音量 1/10、低域カット 20 Hz、SNR 8 dB まで、
  どれも全フレームがビット単位で一致。低域カット 50 Hz では 3 フレームに誤り。雑音 15 dB＋低域カット 20 Hz＋極性反転では最初の LSF を落とした（以降のフレームは全部受信）。
* A1S（デジタル折り返し `dl`）：20 秒・500 フレームを送って受けて、全フレームがビット単位で一致。
  音声処理は 10 ms あたり最大 1.9 ms、復調の遅れは最大 20 ms、Codec 2 の符号化は 40 ms 分で 15 ms（もう片方のコア）。
* A1S（ケーブルでのアナログ折り返し、PHONE 先端 → LINE IN 先端）：10 秒・250 フレーム、30 秒・750 フレームとも
  全フレームがビット単位で一致。LSF も復号、極性は正、EVM 最大 0.20、Golay の訂正 0、ライン入力 -15 dBFS（送信 -10 dBFS）。
* 2 台の A1S での対向（ケーブル 2 本、それぞれ PHONE 先端 → 相手の LINE IN 先端）：
  1 台目の KEY1 で送った 6 回（0.6〜9.6 秒）を 2 台目がすべて受信、LSF も復号、Golay の訂正 0、EVM 最大 0.22。
  2 台目の `tx 10 tone` が 1 台目からピー音として聞こえた。
* 2 台目の A1S はフラッシュ 4 MB（1 台目は 8 MB）。書き込みは `build` の中で esptool に `--flash_size detect` を付けて行った。
* A1S の USB 変換（CP2102）はどの基板もシリアル番号が「0001」なので、Windows は 2 台を同時に認識しない。1 台ずつつなぐ。
* **まだ**：実際の無線機。

## ビルドと書き込み
Codec 2 を `%USERPROFILE%\tools\codec2` に置き、PC 版を一度ビルドしておく（`build_w64\src` にできるコードブックを使う）。
```
m17_modem\pc\build.bat
m17_modem\esp32\idf_env.bat set-target esp32      (初回だけ)
m17_modem\esp32\idf_env.bat -p COM13 build flash
```

## 使い方（シリアル 115200）
| コマンド | 動き |
|---|---|
| `t` | 送信の入／切（KEY1 を押している間も送信） |
| `tx N` | N 秒送信して止まる。自分の送信中に戻ってきたフレームを、送ったものと照合して結果を出す |
| `tx N tone` | マイクの代わりに 600 Hz の試験音（1 秒鳴って 1 秒止まる）を N 秒送る。相手側で耳で確かめる用 |
| `c CALL` | コールサイン（保存される）。**実際の電波で送る前に必ず自分のコールサインに** |
| `s` | 状態（レベル、負荷、極性） |
| `lvl DB` | 送信の振幅（±3 の記号の高さ、dBFS、初期値 -10） |
| `inv` | 送信の極性を反転 |
| `mic DB` / `vol N` | マイクの利得（0〜24 dB）／声の音量（0〜33） |
| `dl` | デジタル折り返し（復調器の入力をライン入力ではなく自分の変調出力にする） |
| `diag` | 出力と入力のつながりの確認（声・変調の各出力に 1 kHz、両方の入力の大きさを表示） |
| `keys` | 15 秒間、KEY1〜KEY6 の GPIO（36, 13, 19, 23, 18, 5）の変化を表示（ボタンの配線の確認） |
| `cap S [tx]` | ライン入力を S 秒（4 秒まで）録って 16 進でシリアルに出す（`tx` を付けると同時に送信）。PC の `m17_rf_test --rx 録音.wav` で復調できる |

## 電波を出す前に
M17 の送信には、無線局の免許に、その電波の型式と付加装置（このモデム）が入っている必要があります（変更申請・届出）。
免許の手続きが済むまでは、ケーブルでの折り返しや 2 台の対向など、電波を出さない試験だけにしてください。
