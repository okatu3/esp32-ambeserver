# DV3000 プロトコル / Protocol

> **English summary** — Packet format `0x61 | length (16-bit BE, payload bytes) | type | payload`. Type 0x00 control,
> 0x01 AMBE channel data, 0x02 speech PCM (160 x int16 BE). Only D-STAR (RATEP `01 30 07 63 40 00 00 00 00 00 00 48`)
> is supported. Private commands 0xF0–0xF4 (Wi-Fi lines only) switch processing stages and read counters for tests.

## パケットの形
```
0x61 | 長さ（2 バイト、ビッグエンディアン、type 以降のバイト数） | type | 中身
```
| type | 意味 | 中身 |
|---|---|---|
| `0x00` | 制御 | 命令 1 バイト ＋ 引数 |
| `0x01` | AMBE（チャネルデータ） | `01 48` ＋ 9 バイト（72 ビット） |
| `0x02` | 音声（PCM） | `00 A0` ＋ 160 サンプル × 16 ビット（ビッグエンディアン） |

## 実装している制御命令
| 命令 | 名前 | 動き |
|---|---|---|
| `0x33` | PKT_RESET | 状態を初期化し、`61 00 01 00 39`（READY）を返す |
| `0x34` | PKT_RESETSOFTCFG | 同上（AMBETools の `-r`） |
| `0x30` | PKT_PRODID | `AMBE3000R` を返す |
| `0x31` | PKT_VERSTRING | 版の文字列を返す |
| `0x0A` | PKT_RATEP | D-STAR（`01 30 07 63 40 00 00 00 00 00 00 48`）なら `61 00 02 00 0A 00`。ほかの方式には返事をしない |
| `0x4B` | PKT_GAIN | 入力と出力のゲイン（dB、符号付き）。BlueDV は `4B 05 05` を送る。`61 00 02 00 4B 00` を返す |
| `0x36` | PKT_GETCFG | BlueDV が 5 秒ごとに送る（つながっているかの確認）。`61 00 04 00 36 00 00 00` を返す |
| `0x37` | PKT_READCFG | BlueDV が送信の直後に 1 回送る。`61 00 04 00 37 00 00 00` を返す |

`0x36`・`0x37` の 3 バイトの値（本物のチップが起動時に読む設定）は、本物の DV3000 の値がわからないので 0 にしています。
本物の DV3000 の返事を記録できる方がいたら、教えてください。

## 調整用の独自命令（Wi-Fi の系統 `esp32` / `s3` だけ）
試験のときに、処理を切り替えたり、数字を読んだりするための命令です。普段の使用では送られません。

| 命令 | 中身 | 動き |
|---|---|---|
| `0xF0` | `<追従の強さ×100> <最大の跳び×100> <連続性の重み×100> <フラグ> [...]` | 符号化器のピッチ追従と、前処理のオン・オフ（フラグ：1 = 低域カット、2 = ゲート、4 = フレームの情報、8 = 雑音抑圧） |
| `0xF1` | — | フレームごとの情報（フラグ 4 のとき） |
| `0xF2` | `<番号> <値 int16 BE>` | 調整値を 1 つ変える（下の表） |
| `0xF3` | — | 復号したフレームの値（F2 の 12 番 = 1 のとき） |
| `0xF4` | `[01]` | **`s3` だけ**：届いたバイト数・パケット数・壊れたパケット数・届いた声の大きさを返す（`01` で読んだあと 0 に戻す） |

F2 の番号（`esp32` 系統の既定値）：
| 番号 | 項目 | 番号 | 項目 |
|---|---|---|---|
| 1 | 振幅の求め方 | 12 | 復号の情報を出す |
| 2 / 3 | 有声の判定のしきい値（上 / 下）×100 | 13 / 14 / 15 | 帯域ごとの有声の切り方 |
| 4 | 高域強調 dB（既定 0） | 16 | オクターブ下の修正の比 ×100 |
| 5 | 雑音抑圧の周波数方向のなめらかさ | 17 | 無声にする下限 ×100 |
| 6 | スペクトルのなめらかさ ×100 | 18 | オクターブ下の修正の周期性の下限 ×100（既定 50） |
| 7 | 符号化器の前のゲイン dB（既定 +6） | 19 | ピッチを雑音抑圧の前の音で探す（既定 1） |
| 8 | ゲートの比 ×10（既定 20 = +6 dB） | 20 | 自動イコライザー（既定 1） |
| 9 | 符号化器の AGC の時定数 ×100（100 = AGC なし、既定） | 21 | 自動イコライザーの最大補正 dB（既定 8） |
| 10 | ゲートを開いたままにするフレーム数（既定 10） | 22 | 自動イコライザーの目標（0 = 自分の声 〜 100 = 他局の平均、既定 100） |
| 11 | ゲートが閉じたらすぐ無音の AMBE を送る（既定 1） | | |

## 接続ごとの注意
* **Wi-Fi（UDP）**：返事は、最後にパケットを送ってきた相手に返す。BlueDV は UDP を使う。
* **USB（無印のボードの USB シリアル）**：ボードの自動リセット回路のため、PC が **RTS だけ ON** でポートを開くと
  ESP32 がリセットされたまま止まる。リセットのあとは、チップの起動メッセージ（約 700 バイト）が届く。
* **USB（ESP32-S3 の内蔵 USB）**：PC が **DTR を OFF、RTS だけ ON** にすると、S3 が再起動する。
